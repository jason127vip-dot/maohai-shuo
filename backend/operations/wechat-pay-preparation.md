## 先办理商户号

1. 从 [微信支付公众号接入指引](https://pay.wechatpay.cn/static/applyment_guide/applyment_detail_public.shtml) 进入官方申请，按实际主体准备营业执照、负责人身份证、结算账户等材料。
2. 申请时选择公众号经营场景，并申请 JSAPI 支付权限，填写当前公众号的 AppID。未完善的公众号可按指引提供商品或服务页面的设计稿；当前套餐页可供整理申请截图，是否符合要求由微信审核。
3. 完成平台要求的审核、账户验证和签约。在商户平台「产品中心 → JSAPI支付」核实权限开通。
4. 确认商户号与当前公众号 AppID 的授权绑定；需要时在商户平台发起，在公众平台确认。
5. 由商户管理员在「产品中心 → 开发配置 → 支付授权目录」配置实际网站的支付页面目录。上线前按最终域名、HTTPS 和实际调起路径核对。

申请要求、主体资格和实际审核结果以官方平台为准。本轮不代替用户提交申请或上传身份资料。

## 开通后准备的服务端参数

| 参数 | 用途 |
| --- | --- |
| 商户号 `mchid` | 指定收款商户 |
| 当前公众号 AppID | 与已有微信登录保持同一应用，且绑定商户号 |
| 商户 API 证书序列号、商户私钥文件 | 签名请求和调起支付参数 |
| API v3 密钥 | 解密支付通知 |
| 微信支付公钥及公钥 ID | 验证 API 响应和支付通知签名 |
| 公网支付成功通知地址 `notify_url` | 接收微信支付通知 |

这些参数现已接入配置结构；私钥与APIv3密钥由服务器保存，不填到前端或聊天中。配置位置和开关见最新更新说明。

## 业务流程（11-20已实现首版）

1. 服务端维护套餐金额，按当前登录用户创建持久订单；前端只提交套餐标识，不决定金额、用户或 OpenID。通过已有身份表读取当前公众号 AppID 对应的 OpenID。
2. 后端调用 JSAPI 下单，返回签名后的调起参数；页面调用微信浏览器支付能力。用户取消后允许恢复同一待支付订单，超时或结果未知时先查单。
3. 通知先验签、再解密，核对商户号、AppID、订单、币种和应付金额、付款用户及成功状态。查单与通知均进入同一幂等结算逻辑，事务更新订单与权益。
4. 页面展示的支付回调不能单独触发充值；后端确认付款后再展示已开通的权益，避免重复通知重复发放。
5. 生成任务的服务端额度判断同时检查套餐剩余次数与到期时间，按实际扣减的套餐记录消费及失败退还，已到期次数不可用于新任务。前端应显示各套餐剩余次数及到期时间，不能只靠当前汇总余额判断付费权益。

用户已确认并实现：每次购买独立计时，优先扣快到期的套餐，免费次数最后使用；按北京时间计算自然月／年，月末取对应月最后一天。不得把1个月直接替换为30天、1年直接替换为365天。
