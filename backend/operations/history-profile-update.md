# 历史作品和可选微信资料更新（2026-11-19）

## 行为

- 顶部「我的作品」进入 `/history`，展示当前登录账号成功生成的图片，按创建时间倒序，每页 20 张。点作品可查看大图、保存；零额度仍可查看。旧的微信账号成功任务也会显示，前提是数据库记录和服务器成品文件仍在。
- 作品页顶部显示微信昵称、头像及剩余次数。未同步资料使用默认头像和「微信用户」。点击「同步微信资料」先说明用途，再由用户主动进入 `snsapi_userinfo` 授权；可暂不同步或在微信取消。
- 原登录继续使用 `snsapi_base`。可选资料授权只更新原账号，取消或失败不修改账号、余额、图片；不会注册另一个账号或增加初始次数。
- 更换微信昵称或头像后可点击「更新微信资料」手动同步；头像地址来自微信，后端不下载头像文件，微信地址失效时展示默认头像。

## 数据结构和管理 portal

新字段保存在 `maohai_users`：`nickname`、`avatar_url`、`profile_updated_at`，未授权时文本为空、时间为空。通过 `maohai_wechat_identities.user_id = maohai_users.id` 关联 `app_id`、`open_id`。内部用户 ID 仍是作品、额度和未来订单的关联依据，昵称不能用作唯一身份。

`operations/wechat_user_stats.sql` 已增加用户昵称、头像和 OpenID，只供服务端管理查询，禁止原样暴露为公开接口。当前没有实现管理 portal 或支付。

OAuth state 新增 purpose 和发起同步的内部 user_id。回调校验浏览器绑定及一次性 state，服务端向微信换取用户资料，只在返回 OpenID 对应原用户时保存。授权 token 不持久化、不下发页面、不写业务日志。昵称最多保留 64 个 Unicode 字符；头像只允许受信微信域名并使用 HTTPS。

## 更新顺序

1. 备份数据库、当前 `backend/maohai.exe`、`www`。不要删除数据目录或执行旧账号清理 SQL。
2. 在已执行 001、002 的数据库中审阅并执行 `migrations/003_history_wechat_profile.sql`。它只新增字段和索引，可重复执行，不清空用户或余额。应用启动只检查结构，不自动建表。未同步资料的老用户可以继续使用。
3. 停止 Go 后端，替换 `backend/maohai.exe`；更新 `www/index.html`、`www/assets`、`www/favicon.svg`，保留服务器的 `web.config`、验证文件、配置、字体及 data。保留旧 hash 资源直到确认用户更新，以便浏览器中的旧页面仍可加载资源。
4. 启动后端。无需改数据库连接、AppSecret、回调地址、额度设置或 Nginx。现有 Nginx `/api/auth/wechat/` 与 IIS `/api/` 代理已覆盖新增路径。ARR 保持取消「Reverse rewrite host in response headers」。
5. 微信打开 `/history?v=20261119` 获取新首页文档。长期应给 `index.html` 设置 `Cache-Control: no-cache`，让浏览器重新验证首页；不要把固定版本参数作为唯一更新机制。新资源有独立 hash。

## 微信内验收

1. 同一微信登录，进入我的作品：看到旧成功图片，点击图片查看大图、长按保存。失败/排队任务不列入成功图片列表；本入口不重新调用模型。
2. 点击同步 → 暂不同步，作品仍能使用；再同步 → 微信拒绝授权，回到作品页且余额不变。
3. 同意微信授权：展示昵称、头像；退出重新登录或重启后端仍保留，数据库用户资料字段可查询。只有公众号具有 `snsapi_userinfo` 权限时才能读取。
4. 另一个微信只能看到自己的作品；不能用不同微信的授权覆盖原账号资料。无需为了验证历史列表额外调用付费模型。
5. 多于 20 张作品时查看更多，新生成图片插入后不会造成旧页偏移和重复。

本地测试使用内存库、假的微信 HTTPS 响应及浏览器测试数据。线上微信昵称头像授权、Neon 迁移及服务器部署须在更新后真机验收。资料授权规则参考 [腾讯官方文档](https://docs.cloudbase.net/integration/wechat-official-oauth)。
