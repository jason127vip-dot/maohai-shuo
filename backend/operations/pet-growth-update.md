# 宠物档案与成长轨迹更新（2026-11-19）

## 首版功能

- `/pets` 新建、编辑多只宠物，填写名字、猫狗类型、生日或估计年龄，选择内置头像图标。第一只自动成为默认宠物，也可改设另一只为默认；暂不提供自定义头像照片上传或删除档案。
- 制作页选择当前宠物，默认使用默认宠物；可继续选择「暂不关联宠物」。可开关成品中的名字与年龄，选择宠物或显示选项变化会使用新的提交编号，站内管理资料往返保留照片与选项。
- 宠物资料尚未读完时不接受生成提交，避免遗漏默认宠物；读取失败可重试，或明确选择暂不关联继续。重新读取后保留用户已作出的不关联选择。
- 成功作品自动归入所选宠物的 `/growth` 时间轴，按月份分组，每页20张。支持查看大图、保存成品、补写和修改最多200字的成长记录。
- 旧作品显示在「未关联宠物的作品」，可手动归属。关联时按旧作品日期计算当时年龄，不修改成品文件，不调用模型，不扣额度；已经归属的作品不会转移给另一只宠物。
- 作品记录包含生成时的宠物名字、年龄、日期及显示开关。之后修改名字或生日，不改写既有作品资料和成品。记录文字是独立备注，不写入已经生成的图片。
- 原有我的作品仍展示当前账号全部成功作品，并显示已关联宠物资料；零额度也可管理宠物、查看轨迹和补写记录。资料和作品均按账号隔离。

## 年龄与图片文字

生日用不带时区的日期保存；年龄计算及作品纪念日期统一使用生成时的UTC日期。按完整年月计算，未满一个月显示天数；不确定生日时由填写的年龄估算生日，并始终显示「约」。早于该宠物生日的旧作品不臆造年龄。

名字、年龄与日期由Go在模型出图后绘制到成品；不要求模型生成中文。沿用供应商适配及原有原图清理流程，不额外持久化上传原图。

中文成品文字需要在 `storage.font_path` 配置含相应字形的已授权TTF/OTF字体，**后端demo模式显示中文名字/年龄同样需要配置**。只使用内置英文字体时，可关闭文字显示继续生成。提交前检查实际文字字形，缺字则在扣次数、上传模型前返回明确错误；避免模型成功后才发现文字无法绘制。浏览器前端mock使用本机字体进行预览。

## 数据结构与接口

迁移 `migrations/004_pet_growth.sql` 新增 `maohai_pets`，并为任务增加宠物ID、名字年龄快照、显示开关和备注。宠物与任务通过复合外键约束同一账号，每个账号最多一个默认宠物；修改默认项在用户级事务锁内完成。

| 接口 | 用途 |
| --- | --- |
| `GET /api/pets` | 当前账号的宠物列表，包含当前年龄 |
| `POST /api/pets` | 新建档案 |
| `PATCH /api/pets/:petId` | 编辑本账号档案／设为默认 |
| `POST /api/generations` | 原multipart增加可选的 `petId`、`showPetLabel` |
| `GET /api/generations?petId=...` | 仅该宠物的成功作品，沿用cursor分页 |
| `GET /api/generations?petId=unassigned` | 当前账号尚未归属宠物的作品 |
| `PATCH /api/generations/:taskId/pet` | JSON `petId`，手动归属旧作品 |
| `PATCH /api/generations/:taskId/note` | JSON `note`，编辑成长记录 |

所有业务接口需要现有会话。其他账号无法读取宠物轨迹、修改资料、关联作品或编辑备注；修改请求沿用来源校验，覆盖POST和PATCH等写方法。微信授权允许返回 `/pets`、`/growth`。

重试先按当前用户和提交编号查询原任务并校验输入，直接返回已保存快照，不受之后改名、年龄增长或字体变化影响。新提交仍检查实际文字字形，预占事务保留并发下的幂等检查。
